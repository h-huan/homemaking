# 家政 SaaS 继续开发设计

基于已发布的 `saas-platform` / `502a15e` 继续开发。沿用现有 HM 单体与租户边界，保留现有迁移成果。范围来源于用户在主对话确认的业务闭环及官网/小程序要求。

## 业务实现

- 排班以服务人员的日期班次、技能、服务区域、请假和半小时订单占位共同计算。未指定人员也必须实际选定符合条件的人员后占位；不再提供无产能承诺。数据库事务及人员行锁序列化竞争，唯一 slot 约束兜底。改约在同一事务重新验证并交换占位，失败保留原预约。
- 人员绑定现有后台账号，由租户管理员建立；工作台只访问自己的订单，明确接单/拒单、到达、开始、前后凭证、完成/异常的状态边界。所有履约记录有操作者和时间；不把公开图片 URL 当成私有凭证。
- 售后记录连接受控退款回执，按支付系统存量记录验证租户、商户订单、退款金额与结果；重复通知幂等。结算按已确认净收款快照分配平台/门店/人员，退款产生冲正；结算单和人工打款记录具有审核与审计链，不自动转移真实资金。
- 配额由总部设置，租户无法自增；创建对象及发送渠道处服务端执行。限制门店、人员、服务、客户、每月订单/短信以及独立域名、公众号、小程序的可用性。

## 内容与视觉

- 门户配置租户隔离，包含站点/SEO、导航、Hero、模块显示与顺序、服务/门店/人员推荐、关于、联系方式、FAQ、页脚。草稿与已发布版本分开；发布前校验 URL、长度、类型和推荐数据所属租户，公开接口只暴露发布内容与公开业务字段。普通文本渲染，不执行用户 HTML/脚本。
- 门户采用 Vue 3 + TypeScript 独立前端，深绿、暖白及少量柑橘色点缀，宽松留白、清晰字号层级与原创图文布局。桌面/手机导航、可展开 FAQ、分类筛选、服务详情、联系/预约入口均可使用；尊重减少动效偏好。
- 小程序保留原生技术栈，重用首页/分类/日程/我的交互语义，重新设计视觉；公共 tokens、按钮、区块、服务/订单卡片和加载/空/错误状态集中维护。图片使用自有/新制作素材及租户提供的授权素材，不复制参考图的品牌、文案和图片。
- 管理端延续 Element Plus，抽取页面容器、状态、图片输入和模块编辑公共组件，提供可实际保存与发布的配置入口。

## 数据与交付

新增结构使用版本化增量 SQL，现有数据库只执行本轮升级，不重跑初始化 SQL；新空库初始化追加相同版本。构建目录、环境变量、Nginx 门户/后台路径与微信发布位置同步记录。所有阶段本地提交；真实支付、微信、生产 MySQL 和正式部署单独标注实测范围。

## 验收重点

跨租户拒绝、后台账号与客户身份区分、无排班不可预约、技能/区域/请假匹配、抢位仅一成功、改约失败保留旧位、重复退款和结算不重复记账、配额并发边界、门户草稿不公开、配置 URL 注入拒绝、手机无横向溢出、公共组件确实复用、发布配置改变公开页面；再次扫描新增源码和提交。
