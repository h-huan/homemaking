# 日常配置与业务操作

适用于 `saas-platform` 当前版本。先按[部署步骤](README.md)更新数据库和三个客户端，再按本页配置业务。所有演示名称均应换成自己的真实内容。

## 首次开业顺序

1. 在系统管理中建立租户、门店管理员和服务人员后台账号，再由超级管理员在「人员权限」分配家政角色模板和门店范围。总部直营使用租户 1；加盟租户使用自己的租户编号。
2. 在「家政运营」建立门店、人员和基础服务。人员档案与后台用户账号是两种编号，需要下一步绑定。停用服务后不再接受新预约。
3. 在服务列表点击「价格与预约规则」，设置规格、加项、区域附加费与预约开始时刻。金额按元输入，后端按分保存；规格时长必须为半小时整数倍。已有订单保留原成交价格。
4. 在「排班中心」选择人员，绑定同租户的后台账号，勾选能提供的服务，填写行政区代码并排班。`*` 表示人员不限制行政区；具体代码必须与客户地址和服务区域一致。服务人员可在自己的工作台申请请假或休息，申请待审核时不占产能；店长批准前系统会检查已有预约，批准后才阻止该时段的新预约。管理员直接登记同样要通过预约冲突检查。所有审批、驳回及撤销保留操作记录。
5. 在「人员权限」给人员账号分配「服务人员」模板（`homemaking:worker:read`、`homemaking:worker:fulfill`）。不应给普通人员「家政运营」管理权限。该人员登录后只看到自己获派且已付款的任务。
6. 在「SaaS 与财务」设置租户配额、功能和结算比例。总部可调整其他租户；租户不能自行提升配额。套餐修改不会追溯修改已有订阅额度，需要重新分配；停用套餐会阻止受限业务操作。
7. 配置自有微信应用、支付渠道和通知模板，完成真实账号联调后再开启实际通知和收款。

## 价格、区域与预约

「规格」可设置独立价格与时长；「加项」按选购数量收费，当前不增加服务时长；「区域」按行政区匹配并追加服务费。未设置区域时不额外限制服务区域，但人员必须满足自己的技能、区域与排班。

运营编辑使用服务版本检查。若提示已被修改，刷新后重新确认，不覆盖另一位运营人员的修改。移除规格/加项会停用历史条目；已成交订单不重新计价。修改旧库中多服务共用的区域时，系统为当前服务复制区域，避免影响其他服务。

预约开始时刻为 08:00–20:30 的整点或半点，服务须在 21:00 前结束；最远预约范围为 90 天。可设置至少提前多久、是否接受当天预约，以及客户取消/改期的截止时间。客户最多自助改期两次；管理员改期仍要验证实际产能。系统只有在技能、区域、班次、请假和已有占位全部允许时才提供可约时间；改期失败保留原预约。

班次模板可批量应用到多个日期。人员工作台展示本人排班、扣除预约及已批准请假后的可服务时段，以及请假休息的状态历史。人员接单、到达、上传服务前照片、开始服务、上传服务后照片、提交完工依次执行。提交后订单进入「待客户确认」，此时释放排班占位，但不会完成订单或生成结算。客户可确认完成，也可先申请售后；无进行中售后且超过品牌设置中的确认期限（默认 48 小时）时系统自动确认。确认方式、服务人员提交时间、确认时间与完整状态变化都保留在订单中。异常说明进入时间线，供门店处理。未付款订单不会进入人员工作台。线上待付款订单超过其 30 分钟支付期限会释放占位；线下待收款预约不按此规则自动取消，应由门店核对、确认收款或主动取消。

## 履约照片

后台订单详情、客户订单详情和对应人员工作台可查看私有照片。只接收 JPEG/PNG，单张不超过 5 MB，每单最多 20 张；服务端校验像素尺寸并重新编码，移除 EXIF 等元数据。照片保存在 `HM_EVIDENCE_ROOT`，不通过公开静态地址访问。

该目录需要持久化、写权限及备份。不要将它设置成 Nginx 的 `root`/`alias`，也不要放在本次发布会替换的版本目录。更换服务器时同时迁移数据库和照片目录，保持相对存储路径。

## 官网与小程序品牌

「品牌与渠道」设置品牌名、Logo、favicon、主色、官网地址、登录页、小程序/公众号绑定与小程序首页模块。「官网内容」设置 SEO、公告、导航、主视觉、按钮链接、区块顺序、内容条目和服务/人员/门店推荐。

官网修改先「保存草稿」，确认后「发布」。只有发布版本对外可见，尚未发布的域名显示未开通。推荐内容必须属于当前租户，评价需先在运营评价页开启展示。模块可启用、停用、排序；图片使用自己的 HTTPS 静态资源或站内路径，链接支持 HTTPS、站内路径和页面锚点。

域名必须完成平台验证，并按 Nginx 模板配置 DNS、TLS 和对应站点根目录。更换文案、模块或品牌配置无需重新打包；修改前端代码、API 地址或小程序 `app.js` 的域名/租户编号则需重新打包或发布。每个小程序使用自己的 AppID 和租户编号，不能在客户端放 AppSecret。

独立官网提供服务展示、分类筛选、详情和联系入口。将主按钮配置到自己已上线的预约渠道；它不会自动生成微信 URL Link。公众号 OAuth 的 `/wechat/callback` 目前由管理端前端提供，因此 OAuth 发起域名应路由到该前端，并完成同租户域名验证，不要把它误配到独立官网根目录。

## 售后与财务

客户可选择补做、更换服务人员、重新上门、部分退款、全额退款或其他补偿。待处理申请可由客户撤销；驳回和非退款补偿完成必须填写说明。补做、换人和重新上门由老板、店长或客服选择时间与人员，后端重新校验技能、区域、班次、请假和占位，然后完整执行接单、到达、开工、凭证、提交完工和客户确认。售后页与小程序订单详情显示不可删除的处理时间线。已付款订单取消会自动创建全额退款售后。

部分/全额退款需有退款权限的老板或财务处理；线下退款先实际退钱再登记流水，线上退款沿原支付应用发起。线上退款失败时，须先在支付渠道确认原请求已经失败，再在售后列表填写核对说明并重试；每次重试使用新的商户退款号并保留失败、核对人和重试记录，不能在渠道结果未知时重试。退款业务回执地址是 `/app-api/homemaking/public/refund-callback`，只使用支付模块已验证并持久化的退款结果；不要将微信原始报文直接发送到这个业务接口。具体支付渠道回调见[部署说明](README.md)。

客户确认或系统超时确认完工后，才按当时的比例保存平台、门店、人员分配快照。服务人员仅提交完工时不提前结算。部分退款会冲正净收入及各方应得金额；重复退款通知不重复入账。比例修改只影响后续生成的分配快照。

服务人员在「我的收入」查看真实分佣流水。所选日期净收入按流水入账时间统计，退款冲正显示为负数；待结算是尚未付款的全部流水，已结算历史按财务实际登记付款时间展示付款凭据。租户未启用人员佣金时页面会明确提示，不会按订单价格推算或显示虚假收入。

在财务页按受益方与账期生成结算单、核对后审批。实际转账由财务在支付/银行系统完成，再回填人工付款流水，执行对账。系统不会自动向银行或微信转账。推荐结算周期用于运营安排；历史支付需先人工对账后才能退款或结算。

## 更新时必须替换的内容

完整清单见[环境变量](environment-variables.md)。私有照片目录通过 `HM_EVIDENCE_ROOT` 配置；权限和支付模式没有新增秘密环境变量。新空库只导入 hm-init.sql；已有数据库按增量升级说明执行尚未应用的版本。管理端上传 `hm-ui/dist-prod`，官网上传 `hm-portal/dist`，后端替换 `hm-server/target/hm-server.jar`，小程序通过微信开发者工具发布。

## 家政角色与数据范围

| 模板 | 功能 | 数据范围 |
| --- | --- | --- |
| 平台管理员（独立授权） | 平台配额、微信归属、分佣规则和全部家政操作 | 平台配置 + 顶部明确选择的业务租户；可跨租户管理 |
| 租户老板 | 业务、品牌官网、通知、人员授权、财务 | 本租户所有门店；不能授予平台权限或提升配额 |
| 店长 | 门店/人员/服务维护、订单履约、确认线下收款、售后驳回、评价、排班与请假审批 | 显式分配的门店；不能新增门店、处理退款或授权角色 |
| 调度 | 派单、改期、排班和查看请假状态 | 显式分配的门店；不能批准、驳回或撤销请假 |
| 客服 | 客户、订单改期取消、售后驳回、评价 | 显式分配的门店；客户须在这些门店有订单 |
| 财务 | 订单核对、收款/退款/冲正、结算生成/审核/打款登记/对账 | 显式分配的门店；全租户财务可选择全部门店 |
| 服务人员 | 接单、到达、服务、照片及异常记录 | 绑定到本人账号的服务任务 |

在「人员权限」选择已有后台账号、模板和门店后保存。不能修改自己的家政授权或覆盖超级管理员；只能处理同租户账号，授权会记录操作人与时间。新建门店不会自动加入已有门店范围，需要补充分配。平台身份不在家政角色模板中分配。已有各租户超级管理员、租户管理员只保留本租户老板权限，不因租户编号、super_admin 或 hm_platform 角色名获得平台资格。

业务账号同时检查系统菜单权限、模板允许的操作、租户与门店/本人范围；平台账号以独立授权为依据，业务查询仍使用明确的目标租户。只勾选菜单或手工调用接口不能扩大范围；收回系统角色或门店授权后随后的请求立即按新范围校验。旧的通用管理权限不作为兜底。为避免误授予其他平台能力，家政员工日常角色应通过此页管理，系统用户管理仅用于账号生命周期管理。

## 收款、退款与冲正

1. 老板在「品牌与通知 → 支付方式」选择支付模式。默认 OFFLINE，不需商户号；BOTH 同时提供线上与线下，ONLINE 在微信商户配置完整时提供线上入口。若线上配置缺失、停用或不属于该租户，则仅提供线下联系方式和付款提示。更改模式不会重算已成交订单。
2. 客户预约仍生成有真实价格的 UNPAID 订单。店长、老板或财务核实到账后，在订单点击「确认收款」，选择现金、微信转账、支付宝转账、银行转账或其他，填写实际发生时间和凭证备注。首次收款按整单应收金额确认；后续已确认的订单变更按差额收款，不支持任意分次收款、抹零或把线下付款当免费单。服务时间已结束的预约应先调整或重新预约。
3. 收款成功后订单进入 PAID，可正常派单、履约和结算。收款流水保存金额、渠道、时间、操作人及备注；网络重试不会重复入账。已发起线上支付的同一订单不能再登记线下收款，必须先核对线上结果，必要时取消后重新预约，避免双重收款。
4. 线下售后申请可部分或全额退款。老板/财务先完成实际退款，再点击「登记线下退款」，填写渠道、申请金额、时间和备注；系统不会代为转账。成功后同步累计退款、订单状态、结算及通知；旧收款凭证不被覆盖。线上订单继续使用「批准退款」走原支付应用原路退款，即使当前租户改成 OFFLINE 也继续处理历史回调。
5. 仅对未开始履约、未退款且无进行中售后的误登记收款，老板/财务可从订单详情点击「冲正」。冲正保留原流水并新增反向凭证，订单回到待收款。已完成服务后需要退钱应使用售后退款；不能冲正来抹掉已发生的服务和结算。冲正本身不是给客户转账。
6. 「SaaS 与财务 → 收支明细」按实际发生时间和授权门店查看收款、退款、冲正、净收款；支持日期范围和分页。新流水从 V005 启用时开始记录，旧付款不伪造人工凭证，仍在订单/结算中核对。支付回调记录操作方为支付渠道，人工记录显示实际后台账号。

退款不改变原收款渠道；退款记录单独记录实际退款渠道。金额以分存储，页面按元显示。上线后运行账号不能通过开放接口编辑或删除收支流水；发生差错必须新增退款/冲正记录。数据库、收支流水与结算记录应纳入同一备份策略。

## 订单地址、价格与差额变更

老板/店长可在订单中「变更地址/价格」，客服可变更地址但不能手工指定价格；客户可在小程序订单详情中选择自己保存的新地址。系统检查订单归属、服务区域、当前人员产能、版本和已确认报价。行政区变化按原订单记录的区域费用计算差额，旧订单缺少区域费用快照时，跨区变更须由老板/店长确认总价。开始履约后、进行中售后或已发生普通售后退款的订单不再改价。

先填写原因及客户确认情况，点击「核对变更」再确认。报价变化后必须重新核对。未付款订单立即更新应收；已付款且不涉及金额变化的地址修改直接生效。已线下付款的涨价生成待补款变更，降价生成待退差额售后，原地址和价格在款项处理完成前保留。店长/老板/财务核实补款到账后点击「确认补款」；老板/财务实际退款后在售后登记退差额。禁止用原整单金额重复收款。

差额处理期间不能派单、接单、开始履约、改期或另开售后。尚未发生款项的变更可从订单详情撤销；客户可撤销自己提出的地址变更。撤销保留记录并关闭对应退差额申请，不能单独驳回退差额来留下不平衡的订单。已生效变更不能删除，新变更继续留痕。多笔收款后的退钱走售后，不能通过冲正其中一笔抹掉整单。

订单详情和小程序保留变更前后地址、价格、预约时间、原因、状态；后台还显示操作人。收款和退款凭证关联变更单，完工按全部实收减累计退款进入结算与统计。新历史记录从 V006 开始，不补造旧改期快照。

当前补退差额支持线下收款订单。已发起线上付款的订单允许不改变金额的地址调整，不能直接改写原支付金额；需要改价时先原路退款并重新预约。线上支付与回调继续按原金额校验，线上补差支付及多笔原路退款分摊仍属后续收口。

## 平台身份与业务租户

平台范围（Platform Scope）通过 system_platform_operator 显式授予后台账号，可管理平台配置和跨租户业务。账号的 account_tenant_id 仅用于核对登录归属。直营业务范围（Self-operated Tenant Scope）与加盟业务范围使用相同的租户隔离；DIRECT 是运营模式，不是平台资格。

1. 使用已有平台管理员进入「家政运营 → 平台身份」，选择账号登录所属租户，搜索已有后台账号，填写原因并确认授权。可以授权任意正常业务租户内的有效后台账号。
2. 顶部显示「平台管理」及当前业务租户，切换前会确认并重新加载页面，避免将上一个租户未保存的表单提交给新租户。普通业务账号仅显示本租户，不提供切换入口。
3. 在平台身份页撤销授权后，现有登录会话立即失去平台权限；独立分配的业务角色继续有效。不能撤销自己的授权，并发互相撤销也不能清空所有平台管理员。
4. 平台账号受到额外保护：业务租户管理员不能重置其密码、改绑资料、导入覆盖或改变角色。停用/删除账号前必须由另一位平台管理员先撤销其平台资格；不要用普通员工账号替代平台维护账号。
5. 「授权与访问记录」查看授权、撤销、迁移和跨租户访问，记录真实操作人、登录归属、目标租户/账号、前后状态、原因和访问路径。请求记录不保存密码、Token 或完整查询参数。
