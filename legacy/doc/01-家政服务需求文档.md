# 01 家政服务需求文档

## 1. 文档信息

- 项目名称：家政服务平台
- 基础项目：`homemaking`（基于 hm-Vue / Spring Boot 3）
- 文档类型：需求文档
- 当前版本：V1.0
- 编写目标：为后台管理系统、小程序端、家政门户网站三端建设提供统一需求基线

## 2. 项目背景

当前项目具备标准后台管理能力，适合承载平台管理、配置中心、权限控制、运营管理等基础能力，但尚不具备家政服务业务闭环。

本次建设目标是在现有项目基础上，新增完整的家政服务能力，覆盖：

- 后台管理系统：业务配置、订单运营、人员管理、内容管理、营销管理、数据统计
- 小程序端：C 端用户下单、预约、支付、评价、售后
- 家政门户网站：品牌展示、服务介绍、服务人员展示、线索收集、内容发布

## 3. 建设目标

### 3.1 业务目标

- 支持多类家政服务在线展示与预约下单
- 支持服务项、价格、时长、区域、人员、时间规则自由配置
- 支持小程序端用户完整完成“浏览-预约-支付-履约-评价”闭环
- 支持门户网站承接自然流量和线索转化
- 支持后台统一配置、统一派单、统一运营

### 3.2 产品目标

- 配置驱动，减少硬编码
- 三端共用一套核心业务中台与数据模型
- 角色边界清晰，后台账号与 C 端用户拆分
- 支持后续扩展到优惠券、会员、分销、阿姨端等能力

## 6. 账号体系设计原则

## 6.1 当前现状

当前项目已有 `sys_user` 后台用户体系，已经承载：

- 后台账号登录
- 角色权限
- 菜单权限
- 部门岗位
- 后台用户管理

因此本项目现阶段不单独新建一套鉴权中心，而是在现有基础上扩展。

## 6.2 本期正式方案

- `sys_user` 作为平台内部统一用户主表
- 平台内部用户包括：
  - 管理员
  - 运营
  - 客服
  - 调度
  - 财务
  - 服务人员
- 小程序 C 端用户单独使用 `hm_customer_user`
- 多登录方式使用独立绑定表，例如 `hm_user_auth`
- 服务人员不是独立用户体系，而是平台用户中的一类角色
- 若后续出现非平台直营服务人员，则按加盟体系管理

## 6.3 平台用户规则

- 平台用户不能自助注册
- 平台用户只能由管理员创建
- 创建时设置初始密码
- 首次登录强制修改密码
- 平台用户可支持多种登录方式，但必须命中已存在的平台用户

## 6.4 平台登录方式

本期及预留设计如下：

- 已有：
  - 账号密码登录
- 本期建议实现：
  - 微信扫码登录
- 预留后续：
  - 手机号验证码登录

其中微信扫码登录规则为：

- 扫码后若无法匹配到已存在的 `sys_user`，则不允许登录
- 扫码登录不是注册方式，只是登录方式扩展
- 若扫码获取手机号，必须能匹配到已存在平台用户信息

## 6.5 小程序用户规则

- 小程序用户使用 `hm_customer_user`
- 本期建议支持微信小程序授权登录
- 预留手机号验证码登录
- 小程序用户不进入后台权限体系
- 首次登录默认走微信小程序授权登录，并在首次登录时获取微信手机号作为预约联系方式
- 后续补充手机号 + 验证码登录方式，作为小程序补充登录入口
- 手机号登录用户默认要求绑定微信
- 若用户未绑定微信，登录后通过弹框提醒绑定，用户可关闭；关闭后下次登录继续提醒，直到完成绑定
- 微信小程序 `AppSecret` 仅配置在后端服务端环境配置中，不下发到小程序前端

## 6.6 原因说明

- 平台管理用户与 C 端消费者属性不同
- 平台管理用户受组织、角色、权限约束
- C 端用户更关注下单、地址、评价、支付
- 服务人员属于平台内部人员时，应纳入平台用户管理
- 现阶段复用 `sys_user` 作为平台统一账户主表，改造成本最低且最稳

## 7. 核心业务场景

### 7.1 小程序预约下单

1. 用户进入小程序
2. 浏览服务类目和服务商品
3. 查看服务详情、价格、可约规则、服务说明
4. 选择服务地址、预约时间、服务规格、附加项
5. 提交订单
6. 完成支付或提交待确认订单
7. 平台派单
8. 服务人员上门服务
9. 用户确认完成并评价

### 7.2 门户留资转化

1. 用户访问门户网站
2. 浏览品牌介绍、服务项目、服务人员、案例、资讯
3. 提交咨询表单或预约线索
4. 后台客服跟进
5. 转化为正式用户或代客下单

### 7.3 后台配置与运营

1. 运营配置服务类目与服务商品
2. 配置预约时间规则、价格规则、区域规则
3. 录入服务人员及技能
4. 查看订单并人工派单
5. 跟踪支付、履约、评价、售后

## 9. 重点业务规则

### 9.1 订单状态

- 待支付
- 待确认
- 待派单
- 待上门
- 服务中
- 待评价
- 已完成
- 已取消
- 已退款
- 异常关闭

### 9.2 预约规则

- 默认按服务商品配置的时间规则可预约
- 非服务区域不可下单
- 停用商品不可下单
- 超过预约截止时间不可下单
- 可配置是否允许当天约

### 9.3 派单规则

- 本期默认人工派单
- 后续可扩展半自动派单
- 派单需校验服务人员技能、区域、排班冲突

### 9.4 支付规则

- 微信支付改为后期开发
- 本期仅保留支付状态、支付渠道、支付回调等字段与流程预留
- 待支付超时取消、支付成功后状态流转，放入后续支付功能接入时一起实现

### 9.5 退款规则

- 未派单前可直接取消退款
- 已派单未上门需客服审核
- 服务完成后默认不可线上自动退款

### 9.6 登录规则

- 平台用户不能自助注册
- 平台用户首次登录必须修改密码
- 平台微信扫码登录必须匹配到既有平台用户
- 小程序首次登录必须支持微信授权进入，并获取微信手机号
- 小程序后续增加手机号验证码登录方式
- 手机号登录后默认要求绑定微信
- 未绑定微信用户每次登录后均需弹框提醒，可关闭但不视为完成绑定
- 微信相关敏感配置如 `AppSecret` 仅允许在后端环境配置中维护

### 9.7 通知规则

- 本期文档需预留通知能力
- 后续支持用户下单通知、服务人员任务通知、订单状态变更通知
- 通知渠道包括：
  - 小程序订阅消息
  - 公众号通知
  - 后续短信通知

说明：

- 通知能力列入下一阶段建设
- 本期设计中需预留消息模板与发送记录能力

## 10. 非功能需求

- 后端统一接口前缀：`/api`
- 后台管理端保留现有权限体系
- 小程序与门户共享业务接口，但鉴权体系独立
- 关键操作保留审计日志
- 核心业务对象支持状态字段与逻辑删除
- 重要配置尽量参数化，减少写死逻辑

补充：

- 小程序导航与首页内容需支持运营配置
- 门户首页内容需支持后台发布后自动生效
- 关键业务表需预留组织归属，支持加盟扩展

## 12. 风险与关注点

- 若把 C 端用户直接混入 `sys_user`，后台权限语义会被污染
- 若不预留多登录方式绑定，后续扩展微信扫码与验证码登录成本会升高
- 若不预留加盟组织归属，后续直营与加盟的数据权限会大改
- 预约规则和价格规则设计过死，后续会频繁改库改代码
- 服务人员排班若不提前设计，后续派单能力难扩展
- 门户与小程序若内容数据不共用，会增加运营成本

## 13. 需求结论

本项目建议采用“平台统一内部用户 + C 端用户”双主体模型：

- `sys_user` 作为平台内部统一用户主表
- 服务人员属于平台内部用户的一部分
- `hm_customer_user` 作为小程序 C 端用户
- 多登录方式通过绑定关系扩展
- 加盟能力在设计阶段预留组织维度

家政服务业务统一沉淀为 `hm_` 业务域模块，由后台、小程序、门户网站共享。

## 14. 当前版本补充说明（2026-04-09）

### 14.1 小程序“我的”页补充

- “我的”页当前拆分为“服务入口”和“内容服务”两组。
- 服务入口默认包含：我的订单、服务日程、地址管理、联系客服。
- 内容服务默认包含：隐私政策、服务说明、关于我们。
- 支付、会员、卡包、优惠券相关入口继续不纳入当前版本。
- “我的”页菜单支持后端通过 `hm_mini_home_config` 的 `mineMenuList` 动态配置；若后台未配置，则前端按默认菜单兜底。

### 14.2 小程序服务日程补充

- 服务日程页作为底部 tab 保留，同时在“我的”页中提供快捷入口。
- 服务日程页默认按月展示用户预约订单，并按订单状态显示待上门、服务中、已完成等标识。
- 未登录用户进入服务日程页时，只展示页面框架与登录引导，不主动跳转登录。
- 点击具体日程项后进入订单详情页。

### 14.3 小程序内容页补充

- “隐私政策”“服务说明”“关于我们”等内容型入口，统一进入小程序内容详情页。
- 内容详情页数据来源于后端正式内容表 `hm_portal_content`。
- 当前约定内容类型包括：`privacy_policy`、`service_guide`、`about_us`。
- 后端仅返回已发布内容，未发布或未配置时视为不可用。

## 15. 当前版本补充（2026-04-10）

### 15.1 小程序运营配置改为结构化后台配置

- 管理端不再使用 JSON 文本直接编辑首页运营配置。
- 首页分类导航、活动卡片、平台保障、“我的”页入口、联系方式统一通过管理端结构化表单配置。
- 小程序首页、分类页、“我的”页只负责读取接口并渲染，不再手工维护业务内容。

### 15.2 内容型入口改为后台内容配置驱动

- “我的”页中的隐私政策、服务说明、关于我们等内容型入口，改为读取后台内容配置列表后进行跳转。
- 后台内容来源表为 hm_portal_content，支持内容标识、标题、副标题、封面图、摘要、正文 HTML、发布状态、排序。
- 小程序内容详情接口继续使用 GET /api/mini/home/content/{contentType}，仅返回已发布内容。
- contentType 作为小程序稳定内容标识，在后台保存时要求唯一，避免配置冲突。

### 15.3 小程序图标与图片资源补充

- 小程序首页分类导航、分类页菜单入口、“我的”页菜单入口中的图标，统一改为系统固定图标编码配置，不再由运营直接上传任意菜单图标图片。
- 当前菜单图标配置采用固定图标编码，例如：`clean`、`deep-clean`、`kitchen`、`repair`、`childcare`、`pet`、`order`、`schedule`、`address`、`contact`、`privacy`、`guide`、`about`、`default`。
- 服务项目图片、分类头图、活动宣传图、内容封面图等业务图片，继续由管理端上传并配置图片地址。
- 业务图片除展示地址外，需同时记录存储来源与对象键，便于后续从本地迁移至阿里 OSS、腾讯 COS、七牛云或其它对象存储时不丢失资源定位信息。
- 固定页面结构与排版仍由前端代码维护；所有可替换的业务文案、入口项、宣传图、服务项内容均需通过后台配置生效。
