# 03 家政服务研发优先级排期文档

## 1. 文档信息

- 项目名称：家政服务平台
- 文档类型：研发优先级与排期文档
- 当前版本：V1.0
- 目标：指导研发按业务价值、依赖关系和风险分阶段推进

## 2. 排期原则

- 先打通主链路，再做增强能力
- 先后台基础配置，再小程序交易闭环，再门户内容承接
- 先实现“可下单、可管理、可履约”，再做“可运营、可加盟、可通知”
- 高耦合基础能力优先
- 预留设计可以先于开发实现

## 3. 优先级分层

### P0 核心必做

- 统一用户与登录模型落地
- 家政核心业务表落地
- 后台服务配置能力
- 小程序下单主链路
- 订单管理与派单
- 微信授权登录
- 微信手机号获取
- 未绑定微信提醒机制

### P1 重要增强

- 门户网站基础内容发布
- 小程序首页运营配置
- 评价与售后
- 加盟组织基础能力

### P2 预留与下一阶段

- 手机号验证码登录
- 后台微信扫码登录
- 公众号/小程序订阅消息
- 加盟精细化数据权限
- 营销活动与优惠券
- 微信支付
- 支付回调与支付结果页
- 待支付超时关闭

## 4. 研发阶段规划

## 4.1 阶段一：基础底座建设

### 目标

完成账户模型、业务核心表、后台基础菜单与后端基础框架，保证后续业务开发有统一底座。

### 交付范围

- 数据库表结构设计定稿
- SQL 并入 `ry_20260330.sql`
- 后台菜单权限初始化脚本
- 后端家政业务基础模块骨架
- 平台用户与小程序用户模型打通设计

### 任务清单

#### 后端

- 梳理 `sys_user` 与 `hm_customer_user` 的关系
- 设计并创建 `hm_user_auth`
- 设计并创建 `hm_customer_user`
- 设计并创建 `hm_org`
- 设计并创建服务类目、服务商品、规格、附加项、区域、预约规则表
- 设计并创建订单、派单、评价、内容配置表
- 建立基础 Mapper/Domain/Service/Controller 结构

#### 后台前端

- 新增“家政业务”一级菜单
- 新增家政业务二级菜单占位
- 规划页面路由与接口文件结构

### 验收标准

- 数据库表可正常初始化
- 后端项目可正常启动
- 后台菜单可正常展示
- 家政业务模块骨架可正常访问

### 优先级

- P0

## 5. 建议研发顺序

推荐严格按以下顺序推进：

1. 阶段一：基础底座建设
2. 阶段二：后台配置中心
3. 阶段三：小程序核心交易链路
4. 阶段四：后台订单运营与履约
5. 阶段五：小程序运营配置与评价
6. 阶段六：门户网站基础发布能力
7. 阶段七：加盟基础能力
8. 阶段八：登录与通知增强

## 6. 人员分工建议

## 6.1 后端

- 负责数据库建模、业务接口、订单流程、鉴权扩展、内容配置接口

## 6.2 后台前端

- 负责后台菜单、业务管理页面、运营配置页面

## 6.3 小程序前端

- 负责登录、浏览、下单、订单、评价

## 6.4 门户前端

- 负责门户展示、咨询留资、内容承接

## 6.5 测试

- 重点覆盖下单主链路、订单状态流转、派单、支付、评价、内容发布

## 7. 风险提示

- 如果先做门户而不做后台内容配置，后续会频繁改代码
- 如果先做加盟深度能力，会拖慢主链路上线
- 如果先做通知和扫码登录，会打断订单主链路建设节奏
- 如果不先落数据库基座，后面接口会反复返工

## 8. 当前建议结论

当前项目的最佳推进策略是：

- 先完成后台配置和小程序交易闭环
- 门户与加盟做基础版预留和轻量落地
- 扫码登录、验证码登录、微信支付、公众号通知放到下一阶段

这样既能尽快形成业务闭环，也能保证后续扩展空间。
