# 数据库初始化与增量升级

全新部署只需导入一次 [`../hm-init.sql`](../hm-init.sql)，它是独立 SQL 文件，不依赖客户端的 SOURCE 命令，已包含截至 V006 的全部初始化和升级步骤。导入后无需再执行 V002–V006。此目录中的编号脚本用于已有数据库升级。

| 数据库状态 | 执行顺序 |
| --- | --- |
| 全新空库 | 仅 hm-init.sql（已包含 V002–V006） |
| 已完成原五份 HM 初始化脚本的数据库 | V002 → V003 → V004 → V005 → V006 |
| 已完成 V003 的数据库 | V004 → V005 → V006 |
| 已完成 V004 的数据库 | V005 → V006 |
| 已完成 V005 的数据库 | 仅 V006 |
| 旧家政生产库 | 先按 docs/migration/runbook.md 在隔离新库迁移；不要直接执行这些脚本修改旧库 |

维护数据库结构时，保留已发布的增量脚本，按顺序添加下一版本，然后运行 `node tools/migration/build-init.cjs` 更新单文件安装包。发布前运行 `node tools/migration/build-init.cjs --check`，内容不同会报错退出；部署人员直接使用仓库内的 hm-init.sql，无需安装 Node 或执行生成工具。原始分段 SQL 是生成来源，不是首次部署的操作清单。

V002 添加技能、服务区域、日期班次、请假、账号绑定、履约照片元数据、订单履约/改期字段、官网草稿/发布、套餐配额、分佣及结算明细。V003 补充管理菜单。V002 为一次性 DDL，执行成功后登记 `hm_schema_upgrade.version='V002'`；V003 登记 V003。V004 新增人员角色范围、门店授权、授权审计以及细权限菜单；也是一次性 DDL。

执行前停止应用写入，完整备份数据库并验证恢复能力。使用有 DDL 权限的安装账号逐份执行，遇错停止，不使用 `mysql --force`。MySQL DDL 不能由一个外部事务整体回滚，部分失败后应恢复备份或核对已执行结构再处理；不能盲目重跑 V002、V004、V005 或 V006。运行账号只需 DML 权限。升级后查询 `SELECT version,applied_at FROM hm_schema_upgrade ORDER BY version;`，应包含 V002、V003、V004、V005、V006，再启动新 JAR。

新预约的产能规则从本轮开始严格执行。升级不会猜测旧人员的技能、行政区和班次；管理员必须在排班页确认并录入。未录入的人员不出现在可预约产能中。已存在的订单和占位保留；旧归档人员配置需结合实际运营规则核对后录入。

新增运行变量 `HM_EVIDENCE_ROOT` 指向私有持久目录，例如 `/var/lib/hm/evidence`。目录由后端账号读写、不得暴露为静态目录。数据库保存照片元数据，图片保存在该目录；两者须一同备份与恢复。不需要重新配置数据库密码进 JAR。

回滚前先停止写入。新版本产生订单、照片或结算明细后，直接换回旧 JAR 会失去对应业务能力；应通过备份恢复或专门的数据兼容方案完成回滚。不要删除数据表来掩盖升级失败。

V004 不把旧 `homemaking:manage` 自动升级为全权限。升级后由已有超级管理员登录「家政运营 → 人员权限」，为其他后台账号重新分配模板及门店；服务人员还需保留/建立人员账号绑定。模板同时写入系统角色菜单并清理权限缓存。若手工修改系统角色菜单，后端仍以模板作为权限上限。所有账号重新登录后刷新菜单。生产升级不能跳过此授权步骤。

V005 新增租户支付模式（默认 OFFLINE）、订单支付方式/线上截止时间、不可覆盖的收支流水和收款权限。已有线上支付订单继续保留 pay_order_id；旧已付款且无线上支付编号的订单标记 LEGACY，不伪造人工收款凭证。原金额和结算记录保留。旧线下/历史单须人工对账，不能冒用新的收款/退款入口修改历史资金。V005 需与新 JAR、管理端和小程序一起发布；启用新流水后不能直接回退到不认识这些字段的旧订单逻辑。

升级后的模板默认授权：老板拥有支付设置与收退款，店长可确认收款，财务可确认收款/退款/冲正。V005 同步补充已存在模板角色的菜单；重新登录刷新菜单，手工收回的权限可在系统角色中继续收回。变更可通过人员权限重新应用模板。

V006 增加订单变更快照、待处理变更关联、区域费用快照和地址/改价权限。已上线数据库执行一次 V006；新空库继续只执行 hm-init.sql。V006 不猜测旧订单的区域费用，也不补造旧变更记录；跨区改地址缺少历史报价时须由有改价权限的人员确认总价。更新后同步发布后端、管理端及小程序，重新登录刷新新增权限。没有新增环境变量。
